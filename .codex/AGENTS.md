2. If that wiki is unavailable or does not cover the topic sufficiently, fall back to `../obsidian-vault`, starting with its `index.md` and relevant notes.
3. Resolve these sibling paths from the active repository root, not from the current subdirectory or this global instructions file. For repositories outside that workspace, use `/Users/quangkeu95/workspaces/meteora-llm-wiki` and `/Users/quangkeu95/workspaces/obsidian-vault` respectively.
4. Check the notes' recorded program revision and verify implementation-sensitive details against the current program source. When notes and source disagree, use the source and call out the discrepancy.
5. If neither reference source is available, continue using the repository and program source and state that the reference material was unavailable.
